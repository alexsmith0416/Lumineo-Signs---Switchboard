# BCSync_TaskCompletions — shop-floor "Task complete" → stepper + Current Status

**What it does.** When an employee finishes a job task and ticks **Task
complete** on a BC job punch, that department completes on the job's
production stepper (the next one becomes active, BC Project Planning follows)
and the job's **Current Status** moves to the next step's status.

## The pieces

| Where | What |
|---|---|
| BC (`bc/lumineo-planning-ext` v1.0.0.13+) | **Clock In Job** (BC caption "Clock In Project", page ext 58410): always shows "Currently on" + **Complete current task**; the tick is greyed out (Enabled = punched in) unless the employee is punched into a job — the tick completes the job they're LEAVING. **Clock Out Job** (58411): **Task complete**. **Clock In / Clock Out Multiple Projects/Nestings** (v1.0.0.14, page exts 58412 / 58413): a *Mark tasks complete* part (page 58412 over the open punches — Infotech's own Open Project Punches part is `Editable = false`) with a **Task complete** checkbox per open punch, stored in table **58411 "LUM Punch Tick"** (keyed by labor entry line). A ticked punch is recorded when it closes (subscriber on `ICG Labor Entry` OnAfterModifyEvent, `DateTime Out` set) and any ticks still left are recorded when either Multiple page submits; Source = *Multi Clock In* / *Multi Clock Out* (*Punch closed* if something else closed it). The same task ticked twice within 2 min = one completion. Codeunit 58410 records the tick in table **58410 "LUM Task Completion"** inside the punch's own transaction (a failed clock-in/out records nothing). API page **58411** `taskCompletions`. Infotech's labor entries / posting are never touched. |
| Flow (this) | Every 5 min, one run at a time: BC entries above the highest `crfdf_entryno` already copied → `crfdf_taskcompletion` rows, state **pending**. |
| Dataverse | `crfdf_taskcompletion` (`scripts/create-taskcompletion-table.ps1`). |
| App | `store/task-completion-processor.ts` — every 2 min in the open app of anyone who edits the whole Jobs list (Admin / Ops / Developer, real login), but only a tab on the newest deployed build (`services/app-build.ts`: build time vs crfdf_jobsview `appLatestBuild`; an older open tab leaves the ticks to the newer one). Pure rules: `services/task-completion.ts` (which department), `services/status-rules.ts` (which status), editable in **Settings → Status rules**. The Jobs panel lists a job's ticks ("Shop floor · Task complete") with what was done. |

Source: generated by `_gen_taskcompletions_flow.py` →
`BCSync_TaskCompletions-clientdata.json`; packaged by
`_build_taskcompletions_solution.py` → `Downloads\BCTaskCompletions_1_0_0_1.zip`
(solution **BCTaskCompletions**). Edit the generator, never the JSON.

## How the app applies a tick

1. **Department** — the ticked job task's planning lines name labor categories
   (2010 Metal Fab, 2110 Paint…): one department → it; several → the
   employee's roster department if it's one of them, else the first open one
   in flow order; none → the employee's department, else the task description.
   Install labor → the Install step. Not on the job's stepper → **skipped**.
2. **Stepper** — `completeMany` (the editor's click): stamps "Punch ·
   <employee>", pushes the stepper state to BC, and the job-level completion
   when it's the last step. Already complete → left.
3. **Status** — the new first ACTIVE step's rule (all complete → "Every step
   complete"). Only from normal production statuses: holds and special
   statuses (Service, Morton, Billboards, Refurb, Complete to Admin /
   Invoiced, Ready to Send…) are never moved. Already right → left.
4. The row becomes **done** / **skipped** with a sentence ("Completed Paint
   (the task's planning lines) · status MFG - Paint Prep / Paint → MFG -
   Vinyl Cut"). An error leaves it **pending** for the next run — every step
   is idempotent, so two open sessions can't double anything.

Ticks wait while no Admin / Ops / Developer has the app open (overnight) and
are applied, oldest first, when one does.

## Import & test

1. Run `scripts/create-taskcompletion-table.ps1`.
2. Import `BCTaskCompletions_1_0_0_1.zip`; bind **Microsoft Dataverse**; turn it on.
3. In BC UAT: punch a test resource into a job task, open **Clock In Job** for
   another job, tick **Complete current task**, submit.
4. Within ~5 min the flow copies it (row **pending**); within ~2 more an open
   Admin / Ops session applies it: the stepper step completes and the status
   moves. The Jobs panel → *Shop floor · Task complete* shows the outcome.
