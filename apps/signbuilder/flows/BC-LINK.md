# Sign Builder ↔ Business Central link

The app never calls BC (Switchboard's rule — see `BC-CONNECTIONS.md` in the
Switchboard repo). Flows move the data:

| Direction | How |
|---|---|
| BC opportunities → app | **BCSync_SBOpportunities** reads the Sign Builder extension's `opportunities` API page into Dataverse `crfdf_bcopportunity`. It runs when the app adds a `crfdf_syncrequest` row of kind `sbopportunities` (the opportunity picker does when it opens, at most every 10 min, and on **Refresh from BC**). |
| BC projects → app | **BCSync_SBJobs** reads the extension's `projects` API page (every status but Completed — Planning and Quote too) into `crfdf_sbjob` for the job picker, on a `crfdf_syncrequest` of kind `sbjobs` (the job picker asks on open / Refresh). Switchboard's `crfdf_bcjob` only has Open projects, so it isn't used. "In BC now" in Generate to Project is Switchboard's `crfdf_jobdesc` (Open projects, hourly). |
| App → BC descriptions | **Generate to Project** adds a `crfdf_sbdescpush` row (Status `pending`). **BCPush_SBDescriptions** finds the project on the extension's `jobDescriptions` API page and PATCHes the ticked descriptions (written MSDos by `LSB Job Description Mgt.`, like text typed in BC), then sets Status `synced` / `failed` + a message. Setting a failed row back to `pending` retries it. |
| BC → app (links) | **Open in Sign Builder** on the Opportunity and Project cards opens the app with `?opportunityId=` / `?jobId=` — the app opens that spec or starts one, filled from the opportunity / project. |

Both flows and the extension pages point at **UAT** (like Switchboard's write-back flows).

## Turning it on (once)

1. **Publish the extension** v0.12.1 to UAT (VS Code → AL: Publish, the "UAT sandbox" launch config).
2. In BC UAT: **Sign Builder Setup → Sign Builder App (link)** = the app's play link
   `https://apps.powerapps.com/play/e/484cdd3c-4409-e741-bbd5-7c210e00310e/app/ab0a4994-727d-4255-b399-efaf864c501a?tenantId=fe0182fa-d183-46ab-8493-9e8ea9c3d0b8`
3. **Create the tables**: `pwsh apps/signbuilder/scripts/create-signbuilder-bc-tables.ps1` (device code, sign in as asmith).
4. **Build the flows** with the secret (it goes into the zip in Downloads only):
   `$env:BC_CLIENT_SECRET="<secret>"; node apps/signbuilder/flows/build-bc-flows.mjs --zip`
5. **Import** `Downloads\SignBuilderBCLink_1_0_0_2.zip` (make.powerapps.com → Alex Smith's Environment → Solutions → Import). Bind the Dataverse connection reference to the existing connection. **Delete the zip afterwards.**
   Without the secret in step 4, run Switchboard's `apps/scheduling/scripts/copy-bc-secret-to-flows.ps1 -Targets BCSync_SBOpportunities,BCSync_SBJobs,BCPush_SBDescriptions` (re-run it after every import — importing resets the secret).
6. **Turn the three flows On** (they import Off).
7. **Test**: in the app open a spec → Opportunity No. **Pick…** (it asks BC; the list fills) → pick one. Then on a UAT test project: **Generate to Project…** → Send to BC → "Written to project … in BC." → check the Project Card in BC.
